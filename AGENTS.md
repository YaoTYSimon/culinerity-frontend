# Culinerity

Cheaper, healthier swaps for what you crave, for anyone in Melbourne. React 19 + Vite 8 + Tailwind CSS v4 web app, with a platform-free core package and an optional reference-data server. Requires Node >= 22.

## Layout

- `packages/core` (`@culinerity/core`): platform-free TypeScript. Domain types, scoring, swap ranking, the `swapService`, source interfaces, mock and HTTP sources, and the `ProfileStore` interface. No `window`, `document`, `localStorage`, React or Node APIs (a test enforces this).
- `server` (`@culinerity/server`): Hono + better-sqlite3 API for reference data only (cravings, swaps, prices, nutrition, support places). See `server/README.md`. Never stores anything about a person.
- `src/ui`: React components. `src/App.tsx` is the shell and view switch (plain state, no router): `welcome`, `checkin`, `number`, `swaps`, `budget`, `support`, `nearby`, `food`, `meals`, `week`, `policy`, `tradeoffs`, `pantry`, `cook`, `whatif` (the `View` type in `src/ui/views.ts`; the Menu lists them, and the footer links to `policy`).
- `src/theme`: `tokens.ts` (the single TypeScript source of the four theme palettes), `ThemeProvider` (sets `data-theme` on `<html>` and persists the choice).
- `src/assets/photos`: the 13 bundled Wikimedia Commons photographs (10 cravings, 3 home-cooked welcome photos) and `credits.ts`. Drawn illustrations in `src/ui/illustrations` are the fallback for cravings without a photo.
- `src/services`: `createServices` (the only place concrete sources and the profile store are wired for the web app; the theme store is the one exception, built in `src/main.tsx` and passed to the required `store` prop of `ThemeProvider`), `loadServices` (mocks, or HTTP sources when `VITE_USE_BACKEND=true`), `ServicesContext` and `ServicesLoader` (renders the shell at once; the backend catalogue loads in the background).
- `src/auth`: local profiles. `AuthProvider`/`useAuth` (state: accounts, current, `status` locked | signed-in | guest, remove notice), `Gate` (renders `SignInScreen` when locked, else the app tree keyed on the profile id so Lock/Switch discards in-memory state), `LocalAuthService` (implements core's `AuthService` on localStorage/sessionStorage and Web Crypto; never throws), `verifier.ts` (PBKDF2), `storageKeys.ts`. The service is built only in `src/main.tsx`. UI: `src/ui/SignIn.tsx`, `CreateProfile.tsx`, `ProfileMenu.tsx` (header avatar), `Avatar.tsx`. Pure helpers (name/password validation, rate limit, deletion confirmation) live in `packages/core/src/auth`.
- `packages/core/src/budget`: pure budget logic (Monday-week maths that is DST-safe, `budgetSummary` and pace, spend entries with undo, safe money parsing). `packages/core/src/benchmarks`: the typed dataset (`types.ts`), `StaticBenchmarkSource` (`source.ts`: `isOlderData`, `verificationLabel`), Melbourne area helpers (`areas.ts`) and `generated/benchmarks.generated.ts` (do not hand-edit).
- `src/ui` budget and policy: `BudgetView` (+ `BudgetPlate`, `AddSpend`, `BudgetDisclosure`), `PolicyView` (+ `BarRows`, `ScaleRows`, `ShareDial`, `CompactRows`), shared `BenchmarkRows` (`BenchmarkRow`, `figureParts`, `HEADLINE_IDS`: the indicator ids shown first on Budget, the rest under "More figures"), `PlateRim`, `Disclosure`.
- `packages/core/src/food`: cultural-food logic, all pure: `rules` (diet-rule fit; an `unknown` attribute never passes), `allergens`, `rank` (`rankForProfile`), `meals`, `occasions` (`occasionsOn`, `upcomingOccasions`, `dismissOccasion`), `coverage`, `sanitize` (`foodProfile` and `culturalMeals` on `Profile`). `packages/core/src/cultural`: the typed dataset (traditions, occasions, calendar, ingredients, foods, swaps) with `generated/cultural.generated.ts` (do not hand-edit) and `StaticFoodInfo`. `src/ui` food views: `MyFood` (+ `FoodSteps`, `FoodSections`, `FoodSummary`, `TagInput`, `StepProgress`, `ComingUp`), `MealsView` (+ `WeekRing`, `AddMeal`), `OccasionLine`, `foodCopy.ts` (exact strings).
- `packages/core/src/tradeoffs`: the trade-off counter, all pure: `types` (`TradeoffEntry`, `MAX_NOTE` 140, retention 8 weeks), `categories` (ten fixed categories, their exact labels and support tiers), `entries` (add, remove, restore, `sanitizeTradeoffs`, `tradeoffWeeks`: this week, last week, earlier), `support` (`supportFor`, `HELPLINES`, `FOODBANK_FIND_FOOD`, each with a `verifiedOn` date). `src/ui` views: `TradeoffsView`, `AddTradeoff` (+ `NoteForm`), `SupportCard` (+ `HelpDisclosure`), `tradeoffCopy.ts` (exact strings).
- `packages/core/src/pantry`: the pantry model and logic, all pure: `types` (`PantryItem`, `PantryState`, `ShoppingEntry`, caps and `NAME_MAX` 40), `items` (add, remove, `updateItem`, clear, staples, serves), `search` (ingredient search with aliases), `dates` (local-day maths for use-by, best-before, cooked and opened), `sanitize` (`pantry` and `shoppingList` on `Profile`), `match` (`matchRecipes`: cookable, one missing, a few missing, with substitutions and use-soon), `safety` (past use-by set aside, cooked-leftover "eat by", recipe `safetyLines`), `shopping` (missing items to a shopping list, sample total). `packages/core/src/recipes`: the typed recipe dataset (`types.ts`), `source.ts` (`pantryIngredients`, `ingredientName`, recipe lookups) and `generated/recipes.generated.ts` (do not hand-edit).
- `src/ui` pantry and cook: `PantryView` (+ `PantryAdd`, `PantryList`), `CookView` (+ `RecipeRow`, `ServesStepper`), `RecipePage`, `ShoppingList`, `FoodFitNotes`, `UndoStatus`, `pantryProfile.ts` (`withPantry`, `withShopping`), `pantryCopy.ts` and `cookNotes.ts` (exact strings). The recipe page is state inside `cook`, not a route.
- `packages/core/src/whatif`: the what-if engine, all pure and deterministic (no AI, no network): `types`, `scenario` (validation and `parsePercentBp`), `units` (`toWeeklyCents`, integer cents and basis points), `run` (`runWhatIf`: baseline, four Monday-weeks, `ok | needs | invalid`), `explain` (fixed-template plain words), `compare`, `saved` (cap 10, sanitiser, restore), `context` (indicator ids per change kind), `banned` (words the copy may not use). `src/ui` What if view: `WhatIfView` (+ `WhatIfForm`, `WhatIfFields`, `WhatIfNumbers`, `WhatIfResults`, `WhatIfWeeks`, `WhatIfPlates`, `WhatIfContext`, `WhatIfHelp`, `WhatIfSaved`, `WhatIfCompare`), `whatIfDraft.ts` (in-memory draft) and `whatIfCopy.ts` (exact strings). Results and Compare tables carry explicit ARIA roles; keep them.
- `src/storage`: `LocalProfileStore` (profile) and `LocalThemeStore` (theme), both localStorage-backed and never throwing.
- `src/index.css`: Tailwind v4 import, the six colour roles per theme (`:root` and `[data-theme=...]`), `@theme` names (`bg`, `surface`, `ink`, `muted`, `accent`, `accent-ink`), the food-illustration palette, the plate-rim animation, and the shared `focus-ring` / `motion-colors` utilities.
- `scripts/build-benchmarks.mjs`: validates the research JSON and writes the generated dataset.
- `scripts/build-cultural.mjs`: validates `docs/superpowers/research/2026-10-27-cultural-food.json` and writes the cultural dataset (`npm run build:cultural`; a test fails if the committed file is stale). `scripts/computus.mjs` computes Easter dates.
- `scripts/build-recipes.mjs`: validates `docs/superpowers/research/2026-10-29-pantry-recipes.json` against the cultural ingredient table and writes the recipe dataset (`npm run build:recipes`; a test fails if the committed file is stale).
- `scripts/build-foodsafety.mjs`: validates `docs/superpowers/research/2026-11-21-food-safety.json` (no invented numbers: each figure must appear in a cited official source's `read` notes) and writes `packages/core/src/foodsafety/generated/foodsafety.generated.ts` (`npm run build:foodsafety`; a test fails if stale). View: `src/ui/FoodSafetyView.tsx` (`foodsafety` in `View`, Menu "Food safety"), stores and sends nothing (`foodSafetyPrivacy.test.tsx`). Dietitian or food-safety review needed before public launch.
- `scripts/contrast.mjs`: `node scripts/contrast.mjs` checks WCAG contrast of every theme from `src/index.css`.
- `docs/superpowers/`: design specs and implementation plans (the plate redesign is `specs/2026-10-26-welcome-themes-plate-redesign-design.md`).

## Scripts

- `npm run dev`: Vite on http://localhost:8443/ (host 127.0.0.1; `/api` proxies to http://127.0.0.1:8787).
- `npm run build`, `npm run preview`, `npm run format` (oxfmt).
- `npm test`: core, web and server tests (`npm run test:server` runs the server tests alone). `npm run typecheck`: root, core and server.
- `npm run build:benchmarks`: regenerate `benchmarks.generated.ts` from `docs/superpowers/research/2026-10-26-food-security-data.json`. Tests run with `TZ=Australia/Melbourne` (set in `vitest.globalSetup.ts`, also used by core) so daylight-saving cases are deterministic; do not rely on the machine's zone.
- `npm run build:recipes`: regenerate `recipes.generated.ts` from the pantry-recipes research JSON; commit both files.
- `npm run build:map [-- <scratch dir>]`: fetches the Vicmap Admin LGA layer (the one host services-ap1.arcgis.com, 3 tries), keeps the Greater Melbourne councils plus neighbouring land, and writes `packages/core/src/map/outline.generated.ts` (bounds must match `MAP_BOUNDS` in `project.ts`; raw result stays in the scratch dir, never committed).
- `npm run build:places` / `npm run build:centroids`: regenerate the Nearby dataset and the suburb/postcode centroids from `docs/superpowers/research/` (see its README "Places" and "Centroids"); tests fail on drift.
- `npm run build:places-bulk -- --in <scratch>/bulk-places.json` / `npm run check:places-bulk`: build and validate the "Not checked by us" shards in `public/places/` (committed, generated; Overture 2026-11-18.0). Extract first with `node scripts/extract-overture.mjs --release <id> --out <scratch outside the repo>` (needs DuckDB). Refresh about monthly (research README "Refreshing the bulk places"). Never commit raw Overture data. Food relief: only Overture's `food_bank` taxonomy maps to bulk kind `food-relief` (label "Food relief (listing not checked)", no price line, "Check opening hours and who it is for before you go", ordered by distance like every kind); never add broad community, charity, shelter or worship categories; a food relief row within 100 m of a checked place with a similar name is dropped (checked wins). 14 shipped of 19,418; the gate was not passed and the tier is not checked.
- `npm run seed`: create and fill the local SQLite database. `npm run server`: start the API on 8787.
- `npm run dev:all`: server and dev server together. Use `VITE_USE_BACKEND=true npm run dev:all` to run the web app against the server.

## Product flow

- First visit opens **Welcome** (one question, "How much is food on your mind?"). "Find my number" starts the check-in; "Skip to cheaper swaps" goes to the swaps. Either marks `welcomeSeen`; opening Welcome from the Menu does not.
- **Check-in** asks one question at a time (the FIES questions, then the domain questions) with a progress bar, Back and Skip. Finishing saves the score and shows the **number screen**.
- **Number screen**: the score on a plate-shaped dial whose rim fills once (shows its final state under reduced motion), a plain band headline, the history of earlier scores, and a swap nudge. A score below `SUPPORT_BELOW` (40, in `packages/core/src/domain/bands.ts`) also shows a link to **Food support**.
- **Swaps**: search or pick a popular craving; results rank cheaper, healthier swaps with an "Add to my week" button on each. A collapsed "Your budget" holds the optional weekly budget, income and suburb.
- **My food** (Menu, or "Tell us about your food" on Welcome): optional, skippable, five steps (traditions or cuisines, diet rules, things to avoid, occasions, review), then a summary with "Clear my food settings" (Undo) and "Coming up". It never gates anything. With settings, Swaps shows only what fits: allergies hide an item, rules hide or mark "Check the ingredients" (unknown never passes), tradition cravings lead the picklist, and "Fits your kitchen" marks matches. Halal and kosher are conservative: 22 of the 70 foods carry halal `yes` (plain unprocessed produce, pulses, grains and eggs only, from a secondary definition page, Wikipedia "Halal"), kosher `yes` is on none, and everything else is `unknown`, so those rules mostly show "Check the ingredients". A halal-authority or community review is still open. The line above the list never claims a match: "Showing swaps that avoid what you told us to avoid. This is a guide, not a certification. Check labels." Without settings Swaps behaves as before.
- **Meals that felt like home** (Menu): a calm Monday-week ring and a two-tap log (pick a tradition, optionally a dish and who with), this week and last, with Remove and Undo and "Clear my meals". No streaks, scores, targets or counts pushed at the person; meals older than 8 weeks are dropped.
- **Trade-offs** (Menu, "What we went without"): a private record of what keeping food on the table cost. Ten fixed categories, two taps to log (pick, optionally Change day), an optional note of up to 140 characters, this week and last with Remove, Undo and "Clear all my trade-offs". It shows a plain count sentence and never a score, streak, target or comparison; "0" is never printed. After a food, money, health or child category a calm support card appears (Lifeline 13 11 14, Kids Helpline 1800 55 1800, National Debt Helpline 1800 007 007, Foodbank Find Food at https://findfood.foodbank.org.au/; numbers re-verified 29 October 2026) and "Need a hand?" always holds the same help. Entries older than 8 weeks are dropped. It feeds nothing else: not the score, bands, Budget, My week or the share text. **Open decisions:** a practitioner review of the category wording, the reflection line and the support card; the optional printable summary is designed but not built, pending a decision (it is the only piece that would move this data onto paper); and whether 8 weeks is the right retention.
- **My pantry** (Menu): optional. Add what you have in two taps (starters) or a few words (a searchable combobox; free text only through "Add anyway", and free-text items are never used for recipes). Optional quantity and date per item (use-by, best-before, cooked on, opened on), "Things I always have" staples, Remove with Undo, "Clear my pantry". Grouped "Use soon", "In your pantry", "Set aside" (past its use-by: never offered as food). A shopping list sits under it. Everything stays on the device.
- **Cook with what you have** (Menu): recipes grouped "You can cook this now", "Need one more thing", "Need a few more things", with a serves stepper (1 to 8), what uses an item due soon, substitutions, and a sample price for what is missing. Recipes that break the person's food rules or allergies are hidden, with a count. The recipe page shows grams scaled to serves, steps, NSW Food Authority food-safety lines, nutrition per serve, "Add missing to my shopping list" and Back. No streaks, scores or waste language.
- **Reminders**: one quiet line under the Swaps intro for a chosen occasion that starts within 7 days or is on now ("Diwali starts about Sun 8 Nov."), plus "Coming up" in My food. It is in-page text only: no push, no notification, no service worker. Dates for moon-dependent occasions (Ramadan, Eids, Diwali) are marked "about" and "depends on the moon sighting" where relevant. A reminder can be dismissed, once per occasion and year.
- **Food support**: nearby free food places with a Directions link (sample data unless the server is used).
- **Nearby**: `src/ui/Nearby*.tsx`, `src/location` (`BrowserLocationProvider`, `LocationContext`), places and ranking in `packages/core/src/places`. A starter list of sourced places, nearest first; prices are `stated` or labelled `typical`; dated notices show only while active. Use the dataset only through `PlaceSource`; never add a place without a source, licence and checked date. A second tier, "Not checked by us" (Overture bulk shards, `BulkPlace`, `packages/core/src/places/tier.ts`), shows after the checked list; within it, food relief rows come first as their own short group, nearest first (ruling F2, `splitReliefFirst` in `packages/core/src/places/bulk.ts`; reversible by rendering `ranked` as one list), then the rest by distance; it is labelled as unchecked, has no price or hours, and is shipped on the user's ruling of 2026-11-21 although the quality gate was not passed.
- **My week**: the swaps added in the last 7 days grouped with their savings, "Remove one", "Clear week", and Share (Web Share, else the clipboard, else text to copy by hand). The share text is savings only: never the score, answers, finances, suburb or a name.

- **Budget**: set an optional weekly food budget; add, remove and undo spending; the plate shows what is left, with a pace message, past weeks and what swaps saved. Spend entries live in the profile (on device).
- **Data and policy**: sourced figures with verification labels, grouped by theme, with Melbourne areas by disadvantage and what helps. Reached from the Menu (last item) and the footer.

## Cultural food data rules

- The dataset is `docs/superpowers/research/2026-10-27-cultural-food.json`; refresh with `npm run build:cultural` and commit both files. Never invent a nutrition value, attribute, flag or date: unknown stays `unknown` (and never passes a rule). Nutrition is AFCD Release 3 (CC BY 4.0, attribution to Food Standards Australia New Zealand); prices are sample estimates and flagged "Sample data".
- Traditions name food styles or home-cooking styles, never people. Aboriginal and Torres Strait Islander foods are deliberately not included pending community consultation (the validator rejects them). Rule wording needs a community check.
- The calendar is `approx` for moon-dependent occasions, and its last row must end at least 12 months after today (`npm run build:cultural` prints a warning from 2028-09-20 when less than 12 months remain, and exits non-zero only with `--strict`; tests pin their own date and never depend on the clock: refresh before then). One rule for festivals that span days (Diwali): the row is the main day only (Lakshmi Puja), `approx`, with the span in `note`.

## Pantry recipes data rules

- The dataset is `docs/superpowers/research/2026-10-29-pantry-recipes.json`; refresh with `npm run build:recipes` and commit both the JSON and `packages/core/src/recipes/generated/recipes.generated.ts`. A freshness test fails when the committed file is stale. Never invent a figure, source or step: nutrition comes only from AFCD Release 3 rows already in the cultural ingredient table; `notFound` lists what was looked for and not found.
- **Prices are sample estimates**, a typical Melbourne supermarket price per kg rounded to 10c, never observed prices (no price source was read). They are always labelled "sample price" or "sample data"; a shopping-list total shows only when every entry is priced.
- **Exclusions:** raw poultry and mince recipes ship only with an official cook-through source, and every such recipe carries a thermometer step (NSW Food Authority: chicken 74 C, minced meat 71 C); the validator rejects a high-risk recipe that prints a temperature or time figure in a step without a recorded `safetySourceId`, and requires a `cookTargetsC` figure for each raw meat. Soak-and-boil dried beans and chickpeas are not shipped (no official soaking or boiling source was read; canned beans and split lentils are used). Raw seafood and raw fish are not shipped. Curry blends and sauces without a read source for diet flags are left out.
- **Attribution:** food-safety lines are the app's own wording of NSW Food Authority guidance and always show "General guidance from NSW Food Authority (a NSW agency, not Victoria's). (c) State of New South Wales through the NSW Food Authority." (the Victorian pages returned 404). The AFCD credit (CC BY 4.0, FSANZ) shows on the recipe page and Cook footer.
- Recipe wording is the author's own. The pregnancy and weakened-immune-system line is omitted until the NSW PDF can be read (it could not be extracted). A food-safety or dietitian review is recommended before launch.
- Rules and allergies hide recipes but never "certify" anything; an `unknown` attribute never passes a rule (same as swaps).

## Benchmark data rules

- **No invented numbers.** Every figure comes from `docs/superpowers/research/2026-10-26-food-security-data.json` and a source with an https URL, a year and a `verification`: `primary` (read from the source), `secondary` ("Read from a published report that cites it"), `press` ("Press report only"). Change a figure only after reading its source, and put the value, evidence and source in the commit message.
- Refresh: edit the JSON, run `npm run build:benchmarks`, commit the JSON and the generated file. A freshness test regenerates in memory and fails if the committed file is stale. See `docs/superpowers/research/README.md`.
- `note` is plain user-facing text and is shown. `research` records how a figure was found (blocked pages, what was not opened); it is never shown. Keep technical wording out of `note`.
- `decimals` (0 to 4) is how many places the source writes (34.0, 3.0); `figureParts` honours it. String-valued figures use `value: null` plus `display`.
- Different measures are never combined or plotted on one axis. Missing data is listed as `notFound` (tagged `budget` or `policy`), never filled in.
- `isOlderData` flags `dated` figures and any more than five years old; the UI shows "Older data".

## What-if data rules

- Context figures sit in the benchmark dataset under `group: "whatif"` (filtered out of Budget and Policy). They are context only and are never used as arithmetic defaults or pre-filled into a field. Every row needs a source; where no source was found (a typical one-off bill) nothing is shown and the screen says so.
- `refreshAfter` (optional `YYYY-MM-DD`, never shown) marks when to re-read a row's source. `npm run build:benchmarks` prints a `WARNING` for any that has passed (Australia/Melbourne) and exits 0; `--strict` exits non-zero. Dates: minimum wage 2027-07-01, JobSeeker 2027-03-21, Melbourne rent 2026-12-31. Steps are in `docs/superpowers/research/README.md`.
- Money is integer cents and percentages are integer basis points; no float after parsing. Percentages apply to the baseline, never compound.
- The wording of the notice is not legal review.

## Design rules (the plate)

- Flat colour only: no shadows at rest, gradients, hairlines or cards. Tone steps (`bg` then `surface`) separate things.
- Everything is fully round: buttons (`PillButton`), inputs, focus rings, photos (`RoundPhoto`), dots. A photo is never hard-cropped at a screen edge.
- One typeface, Schibsted Grotesk (bundled). Display text is weight 800, tight tracking, sentence case (`.font-display`).
- Touch targets are at least 44px; plain language; motion only through `motion-safe` and the one-time dial fill.
- Use the semantic colour names only (`bg-bg`, `bg-surface`, `text-ink`, `text-muted`, `bg-accent`, `text-accent-ink`). Do not add Tailwind important (`!`) overrides.

## Themes

Nine themes: tobacco (default), sand, walnut, cream, ink, sage, clay, sunrise, mono, chosen from the "Colours" group in the Menu (`ThemeSwatches`). The one list is `THEMES` in `packages/core/src/theme/theme.ts` (ids and names; ids, names and types derive from it); adding a theme means adding it there, in `tokens.ts`, `src/index.css` and the `index.html` no-flash map. The palettes live in `src/theme/tokens.ts` (single TypeScript source, used by `ThemeSwatches`); `src/index.css` must hold the same six values (and the no-flash script in `index.html` the `bg` colour), and `src/theme/tokens.test.ts` fails when they drift. `src/theme/contrast.test.ts` enforces contrast.

To add a theme: add its id to `ThemeId` and `THEME_IDS`/`THEME_NAMES` in `packages/core/src/theme/theme.ts`; add its six values to `THEME_TOKENS` in `src/theme/tokens.ts`, a `[data-theme='id']` block in `src/index.css`, and the `themes` map (bg colour) in `index.html`; then run `npm test` and `node scripts/contrast.mjs`.

## Local profiles

- Optional profiles (name, avatar colour, optional password of 6 to 64 characters; profiles made earlier with a 4 to 8 digit passcode still sign in) all stay on the device. Guest = no profile, using the original keys. Sign-in shows when profiles exist and nobody is signed in; "Skip for now" continues as a guest for that tab.
- Keys: `culinerity.accounts.v1`, `culinerity.attempts.v1` (localStorage), `culinerity.session.v1` (sessionStorage), `culinerity.profile.v1` (guest) and `culinerity.profile.v1.<id>` (a profile), `culinerity.theme.v1` (global). Migration ("Start from my current data") moves the guest profile into the new one and removes the guest copy.
- The lock is access control for casual access, not encryption: the password is never stored (PBKDF2-SHA-256 verifier, 210,000 iterations), stored data is plain, 5 wrong tries pause for 30 seconds (soft limit, reset by clearing storage). Never claim more than this in copy.
- Deleting a profile needs the typed name, removes only that profile's keys, and reports anything it could not remove (`RemoveResult.remaining`); `removeNotice` carries that to the sign-in screen or guest app.
- Every text field uses `FIELD_EDGE`/`INPUT_CLASS` (src/ui/formParts.tsx): a 2px `muted` edge, >= 3:1 on bg and surface in all themes (checked by `scripts/contrast.mjs`). Do not add inputs without it (`fieldEdge.test.ts`).
- To reset a device while developing: `localStorage.clear(); sessionStorage.clear()`.

## Privacy rules

- A person's answers (check-in, score, score history, budget, suburb, My week, theme) stay on their device in localStorage (`culinerity.profile.v1` or `culinerity.profile.v1.<id>` for a local profile, `culinerity.theme.v1`). Sharing the week sends nothing to us. They are never sent anywhere.
- Food traditions, rules, allergies, occasions and meals stay on the device in the profile (`foodProfile`, `culturalMeals`). They are never sent anywhere: not in a request (swaps, prices, nutrition and food-info requests carry ids only, no profile text, headers or body), not in the share text, `document.title`, the URL, `data-` attributes, a notification, a log or any other key. Clearing removes the keys from the stored JSON; deleting a profile removes its key; "Start from my current data" carries both fields over. `src/ui/foodPrivacy.test.tsx` enforces all of this (spies installed before the flow, detectors that are proven live); if one of its assertions fails, fix the code, not the test.
- Trade-offs (`tradeoffs` on the profile, key `culinerity.profile.v1` or `culinerity.profile.v1.<id>`) stay on the device, are kept 8 weeks and are never shared or sent: not in a request, the share text, `document.title`, the URL, `data-` attributes, a notification, a log or any other key; no `navigator.share`, clipboard, beacon or `history` call. They never change the score, band or budget. Clear removes the key from the stored JSON; deleting a profile removes it; "Start from my current data" carries it. The support card and its links write and fetch nothing. `src/ui/tradeoffPrivacy.test.tsx` enforces all of this (detectors proven live); if one of its assertions fails, fix the code, not the test. The printable summary (not built) would need to be opt-in.
- Pantry and shopping list (`pantry` and `shoppingList` on the profile, same keys) stay on the device and are never sent or shared: not in a request, the share text, `document.title`, the URL, `data-` attributes, a log, `navigator.share`, the clipboard, a beacon or any other key. Clear removes them from the stored JSON; deleting a profile removes them. `src/ui/pantryPrivacy.test.tsx` enforces this (spies installed before the flow, detectors proven live); if one of its assertions fails, fix the code, not the test. Matching, dates and prices run locally from the bundled dataset.
- What if (`housingWeekly`, `otherFixedWeekly`, `whatIfScenarios` on the profile, plus the existing `incomeWeekly` and `foodBudgetWeekly`, same keys) stays on the device and is never sent or shared: not in a request, the share text, `document.title`, the URL, `data-` attributes, a log, `navigator.share`, the clipboard, a beacon or any other key. There is no share or export on the page. Saved what-ifs hold the change only, never results or baseline numbers; the draft is in memory only. No LLM, model or AI SDK, and no `fetch` in `packages/core/src/whatif` or the What if views. `src/ui/whatIfPrivacy.test.tsx` and `packages/core/src/whatif/privacy.test.ts` enforce this; if one fails, fix the code, not the test. The UI never says "AI", "smart" or "predict" (`banned.ts`, scanned by tests). **Legal review is pending: do not launch the What if view publicly before it.**
- Location (Nearby) is never stored, put in the profile, shared or sent: one `getCurrentPosition` on a button press, rounded to 3 decimals, held in React state and discarded on leaving the view. No `console.*` in `src/location` or the Nearby views (a test checks privacy).
- No third-party requests: no analytics, CDNs, remote fonts or embeds. Fonts are bundled via `@fontsource`.
- The server only serves reference data and receives no profile data (`/api/cravings/all` and `/api/food-info` are public catalogue reads with no parameters from the person).

## Data

Mock-first. By default the app runs on bundled sample data (prices, nutrition, support places) and labels it "Sample data". Do not present sample data as real.

## Conventions

- SOLID and DRY. Depend on the core interfaces (`FoodCatalogue`, `PriceSource`, `NutritionSource`, `FoodSupportSource`, `ProfileStore`); wire concrete classes only in `createServices` / `createHttpServices` (and the theme store in `src/main.tsx`).
- Keep `packages/core` platform-free. Put browser code in `src`, Node code in `server`.
- Style with Tailwind utilities and the theme tokens; do not hard-code colours (the food-illustration palette is the one exception). Reuse `focus-ring` and `motion-colors` rather than repeating those class strings.
- Accessibility: visible focus, 44px touch targets, plain language, respect reduced motion.
- Every behaviour change comes with a test (Vitest + Testing Library for UI; `*.test.ts` beside the code in core and server).
