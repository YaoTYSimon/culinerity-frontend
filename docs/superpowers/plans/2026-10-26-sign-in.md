# Sign-in (local profiles) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add on-device named profiles with an optional passcode lock and a sign-in screen in the plate design, with per-profile storage, migration, switching, locking and deletion.

**Architecture:** Pure validation/rate-limit logic and the `AuthService` interface live in `packages/core`. Web implementations (`LocalAuthService` with Web Crypto PBKDF2, session in `sessionStorage`) live in `src/auth/`. The UI tree under a signed-in profile is keyed on the profile id so state is discarded on lock/switch.

**Tech Stack:** React 19, Vite, Tailwind v4, TypeScript, Vitest + Testing Library, Web Crypto (`crypto.subtle`).

**Spec:** `docs/superpowers/specs/2026-10-26-sign-in-design.md` (read it whole, including "Builder-check rulings"). Design system: `docs/superpowers/specs/2026-10-26-welcome-themes-plate-redesign-design.md` and the mockups in `docs/superpowers/design/mockups/`; taste skill at `~/.agents/skills/design-taste-frontend` (house rules).

## Global Constraints

- Local only: no network calls, cookies, tokens, third-party identity providers, no email or surname collected. The passcode is **never stored or logged**; only a PBKDF2-SHA-256 verifier (16-byte random salt per profile, 210,000 iterations, 32-byte output, `v: 1`, base64) is stored; comparison is equal-length XOR-accumulate (no early return). If `crypto.subtle` is missing, only passcode-less profiles can be created (calm notice). IDs from `crypto.randomUUID()` with a `getRandomValues` fallback, else creation is refused.
- Honest copy: "A passcode adds a lock, not encryption. Someone with technical access could get around it." Never imply data is encrypted.
- Plate design system: Schibsted Grotesk, fully round shapes (circular avatars, pill buttons), flat colour, themes via tokens, no cards/chips/hairlines/shadows/gradients, AA contrast, `focus-visible`, `motion-safe`, 44px targets, one h1 per screen, focus moves to the heading on each screen change, errors in an `aria-live` region, no horizontal scroll at 320–1280px, phone-first, centred 520px column on desktop.
- "Skip for now" (guest) always available; guest keeps today's behaviour and keys; sign-in never blocks the swap search.
- Existing tests keep their intent (never weaken). Every task ends green: `npm test`, `npx tsc --noEmit` (root, packages/core, server), `npm run build`. Visual tasks are verified with real Playwright MCP screenshots at 390, 320 and 1280 in two themes (clear storage in a fresh browser context first: the Playwright profile persists localStorage; `browser_close` then reopen).
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01CVJsJBKSnSRKS1F3CWccnQ`. Stage only your own files (explicit `git add <paths>`). Never push or merge.
- Vitest pins `TZ` is not needed here, but a Node `webcrypto` setup is (jsdom lacks `crypto.subtle`/`randomUUID`).

## Review Focus

- Wrong passcode × 5 → 30-second pause; the pause survives a reload; a correct passcode after the pause works; with an injected clock.
- Two profiles with the same passcode get different salts and hashes; verifier round-trips; tampered hash/salt fails closed; unknown or corrupt account JSON → empty list, no throw.
- Migration is a **move**: guest `Profile` copied to the new key, verified, then removed; nothing left under guest keys; a failed write leaves the guest data intact and shows a message.
- Lock/switch discards in-memory state (the old profile's data is not reachable from the rendered tree); the session id for a deleted profile → `current()` is `null`.
- Delete requires the exact typed name; deleting never touches the guest keys or other profiles; "Forgot passcode? Delete this profile" works without the passcode.
- No passcode, hash or salt ever appears in console output, the DOM, error messages or the share text.
- `crypto.subtle` or `randomUUID` missing → passcode-less creation still works or is refused with a clear message; storage failure shows a calm message and never throws.
